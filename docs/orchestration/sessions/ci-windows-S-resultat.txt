Commit 68cea63 sur `agent/ci-windows-S`. La suite complète donne 899 tests, 0 échec, 1 ignoré sous Linux. Je ne l'ai pas rejouée sous Windows, donc c'est la prochaine CI qui confirmera.

**Fait**
- **Échec 1 (`test_chemin_absolu_dans_dest`)** : la cause n'est pas celle du prompt. `realpath` normalise déjà les séparateurs. `_ocr_confiner` refusait tout chemin commençant par une lettre de lecteur, donc `C:\...` était refusé comme `C:x`. Le refus ne vaut plus que si le chemin n'est pas absolu (`_lecteur_sans_chemin`), et j'ai ajouté `normpath` avant `normcase` des deux côtés. C'est l'écart 299.
- **Échec 2a (`test_rien_lu...`)** : `deja_present` rend maintenant `normpath(join(dest, rel))`. Écart 300.
- **Échec 2b (`test_deux_entrees...`)** : contrairement au prompt, ce test attend `/` et non `os.sep` (`.replace(os.sep, "/")`), comme la file d'extraction. Le code est corrigé : `a_preparer` est donné en `/` dans `telecharger`, le test est inchangé. Écart 301.
- **Échec 3 (`test_ci`)** : comparaison par `os.path.normcase`. Écart 303.
- **Échecs 4 (les deux tests de fil)** : le défaut est dans le code, pas dans une attente trop courte. Sous Windows, `os.replace` sur `file.json` lève `PermissionError` quand un lecteur tient le fichier. Le test le lit toutes les 20 ms sans verrou, et un antivirus pourrait faire pareil.
  - Un seul refus, simulé sous Linux, reproduit exactement `1 != 4`. Deux refus de suite reproduisent l'attente de 15 s sans `terminee`.
  - Correction : `_ecrire_json` et `_ecrire_texte` passent par `_remplacer_travail` (5 essais, 0,05 s entre deux, `PermissionError` seulement). C'est l'écart 302.
